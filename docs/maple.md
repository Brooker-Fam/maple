# Maple's Log (`/maple`)

A private, collaborative newborn tracker for Maple Jane: nursing (left/right timers), bottles, pumping, diapers with stool colors, sleep, tummy time, baths, temperature, vitals and skin checks, growth with WHO percentiles, notes and questions for the doctor, photos and milestones. Matt and Brittany (and anyone they invite) log from their phones, from Claude or ChatGPT (MCP), or hands-free with Siri. A separate area "for mom" keeps her own medicines, temperature, questions for her OB and check-ins, with warning signs and help lines (see [For mom](#for-mom)).

It's a family side project: unlinked from the public site and `noindex`.

## Setup checklist (production)

1. **Google sign-in: nothing to set up.** Maple reuses the OAuth client the calendar, photos and `/birth` already use, and signs in through `/birth`'s redirect URI (`/api/birth/auth/callback`), which is already registered. That callback hands any sign-in whose `state` starts with `maple.` to `handleMapleGoogleCallback` in `src/lib/maple/google-callback.ts`. The site admin username/password also works on the sign-in screen (you'll appear as "Admin"; rename yourself in Family).
2. **Who can join.** The first Google account to sign in becomes the owner. To be explicit, set `MAPLE_ALLOWED_EMAILS` (comma-separated). If it's unset, `BIRTH_ALLOWED_EMAILS` is used. Owners can also invite by Google email or with a one-time link (no Google needed) from the Family tab.
3. **Private photo storage (recommended).** Vercel → Storage → create a Blob store with **Private** access (e.g. `maple-private`). Copy its read-write token into a new env var `MAPLE_BLOB_READ_WRITE_TOKEN`. Don't connect it with the default `BLOB_*` names, or it will shadow the guest-photo store.
   Without it, photos go to the existing public store under `maple/…` with random names. They're still only ever served through the signed-in proxy (`/api/maple/photo`), but the underlying files aren't access-controlled.
4. **`MCP_SECRET`.** Set it to a long random string. Otherwise MCP tokens are derived from `ADMIN_PASS`, and changing the admin password would disconnect Claude and ChatGPT.

Migrations run on build (`maple_babies` is seeded with Maple Jane, due 2026-10-20).

## Connecting Claude and ChatGPT

Full instructions with copy buttons are at `/maple/connect`. The MCP server URL is `https://brooker.family/api/maple/mcp` (Streamable HTTP; there is no SSE).

- **Claude** (web, desktop, mobile): Settings → Connectors → Add custom connector → paste the URL → Connect → Continue with Google.
- **ChatGPT** (web, developer mode / custom connectors): add a custom MCP server with the same URL and OAuth.
- **Claude Code:** `claude mcp add --transport http maple https://brooker.family/api/maple/mcp`.
- **The existing "Brooker Family Calendar" connector** (`/api/mcp`, admin login) carries Maple's tools too, next to `calendar_exec`, so Matt doesn't need a second connector. Its entries are credited to "Admin" unless an owner signed in with Google turns on Family → Talk to Maple's Log → "Calendar connector logs as me" (`settings.admin_as`, which can only be set to yourself). The Admin row appears in Family after the connector's first Maple call, so an owner can turn it off there. If an owner turns off the admin login for Maple, those tools refuse but the calendar keeps working.

OAuth reuses the site's `/oauth/*` shim. A Maple connection (detected by the RFC 8707 `resource` parameter, or the `maple` scope) signs in with the same Google session as the app, and the token is minted for `maple:<email>`, so entries show "via Claude / via ChatGPT" under the right person.

- **Bound to this server.** Tokens are bound to exactly `https://brooker.family/api/maple/mcp`. Any other resource is refused at consent, so another MCP server can't obtain or replay a parent's token.
- **Calendar and RSVP stay admin-only.** Those MCP servers only accept admin tokens, so a family member's Maple token can't open them.
- **Refresh tokens, for Claude, ChatGPT and local apps only.** A code sent anywhere else (say, a phishing page) gets a 30-day token and no renewal. Each refresh hands out a new refresh token, so connectors in use don't expire. They're stateless, so an old one stays valid until it expires. Admin-login ones last 90 days (the admin login can run code on the calendar and RSVP servers) and die when `ADMIN_PASS` or `MCP_SECRET` changes. Family members' last a year and are re-checked against membership.

## Access and revocation

- **Removing someone** (Family tab) ends everything at once: their sessions, MCP connections (checked on every request and every refresh) and Siri tokens. Removal leaves a tombstone, so an address on `MAPLE_ALLOWED_EMAILS` can't simply sign back in. Inviting them again lifts it.
- **The admin password login** shows up in Family as "Admin". A Google owner can remove it, which turns off the admin password and admin MCP access for Maple only; the calendar and RSVP are unaffected. Delete the `admin` row from `maple_removed` to turn it back on.
- **Changing `ADMIN_PASS`** signs Admin out of Maple, and revokes admin MCP tokens issued since this change.
- **The session cookie** is scoped to `/api/maple` and `/oauth/authorize`, so the `/ingest` analytics proxy never sees it.

## Hands-free (Siri / Shortcuts)

Family → Shortcuts & assistants → Hands-free with Siri creates a personal token. An iOS Shortcut does *Get Contents of URL* (`POST https://brooker.family/api/maple/quick`, header `Authorization: Bearer maple_…`, JSON `{"action":"pee"}`), then *Speak Text* with the response's `speak` field.

Actions: `pee`, `poop`, `both`, `nurse_left`, `nurse_right`, `switch`, `back_and_forth`, `stop`, `sleep`, `wake`, `vitamin_d`, `bottle` (with `amount_oz`), `status`, and mom's `mom_status` and `mom_dose` (see [For mom](#for-mom)).

Going back and forth: `back_and_forth` with a feed running stops tracking sides from now ("Going back and forth from 9:14, so there's nothing to switch."; a side under a minute old turns both instead, and a paused feed goes back on going both). With nothing running it says "Start the feed on a side first.", since the next side alternates from the side she started on. While she's going both (or on a break from it), `switch` says "She's going back and forth, so there's nothing to switch." instead of guessing a side, and `nurse_left` / `nurse_right` track sides again ("Tracking sides again: she's on the left."). A forgotten feed is refused the same way as `nurse_*`. There's no Siri pause: a stop and a new feed within 10 minutes count as one feed anyway. `status` speaks feeds as Today counts them: "Maple last ate 45 minutes ago, starting on the left, so start on the right next." (with ", or whichever side feels fuller" after back and forth), and after a cluster "Maple cluster fed from 6:02 to 8:40 PM: 4 feeds, 1 hour 52 minutes of nursing. She last ate 45 minutes ago, …"; after a long back-and-forth feed it says when she finished and what last fed counts from ("Maple finished a long feed 5 minutes ago, starting on the right and going back and forth. Last fed counts from 40 minutes before she finished: 45 minutes ago. Start on the left next, or whichever side feels fuller."); nursing now, it says when she's going back and forth, when a break began ("Maple is nursing now, on a break since 2:25 AM, 40 minutes in.", never the last side tracked) and which feed of a cluster this is (`lastFedSpeak` in `mcp-tools.ts`, shared with `maple_status`'s `speak`).

`nurse_left` / `nurse_right` during a running feed switch to (or resume on) that side, unless the feed looks forgotten (`staleFeed` in `feed.ts`, the same rule as MCP `start_timer`): nothing tapped on it for an hour, or (with a start time given, on a break) a time over 30 minutes after she came off. It's judged by the newest stretch start/end or tap, not the feed start, so a long cluster feed tapped a minute ago still resumes, and so does one she dozed off for half an hour. A stale one is refused out loud ("Stop that one first, then start the new feed").

## How it works

- **Data** lives in `maple_entries`: one row per event, with `kind` plus JSONB `data` in metric units (g, cm, °C, ml). The UI shows lb/oz, in, °F and fl oz by default.
  - Running timers are rows with `active = TRUE`. A unique index allows one running timer per kind.
  - `client_id` makes retries idempotent.
  - Deletes are soft deletes, so they can be undone.
- **Shared logic** in `src/lib/maple/` is pure TypeScript, used by the browser, the REST routes and the MCP tools alike:
  - `types.ts` holds the shapes.
  - `time.ts` holds time-zone and DST-safe helpers, plus `parseWhen` for times like "3:10am", "20 min ago" and "yesterday 11pm".
  - `feed.ts` is the nursing engine, shared by the server, the app's optimistic updates and previews, and the MCP tools (checked by `npm run check:maple-feed`). A feed is a list of stretches (`{side, start, end}`); the gaps between them are breaks. `feedParts` turns that into what the card and sheets list (Left, Break, Right…), and every fix moves exactly one **moment**: the feed start, a switch, when she came off, when she went back on, or the end (`moveEdge`, with `edgeBounds` for the limits). `setSide` fixes which side a part was, `undoLastTap` takes back a mistaken switch/pause/resume, and `addPart` adds a side to a finished feed. Nothing moves a neighbouring side as a side effect, and a fix never eats past a break.
  - A Switch tapped within 15 s of a tapped resume (one that made its own part) changes the side she went back on instead of adding a second-long part (`resided`; the break stays, and undo still goes back to paused): "Back on the Left, not the Right". A resume given an earlier time is a real part, so a Switch after it is a switch. Switching back within 15 s of a switch still undoes that switch (`reverted`).
  - Words: after a break it's "back on the Right" only when she came off the Right; otherwise "On the Right" / "When did she go on the Right?" (`momentQuestion(moment, side, prev)`).
  - **Back and forth.** A stretch's side is `"L"`, `"R"` or `"B"`: both sides, not tracked (`StretchSide`; `Side` stays L/R for `first_side`, `last_side`, the next side and anything a person picks). `switchTo(data, "B")` ends the side she's on and opens a both part; from a part under a minute old (the toast's "Back and forth" right after a Switch, or a feed just started) that part turns both instead (`resided`, and `last_tap.from` lets undo give it its side back); when that part began right as back and forth ended (Track sides, then Back and forth again within a minute), it joins that stretch, and `last_tap.cut` keeps where it began, so undo, or a side tapped within 15 s, splits it off again instead of giving the whole stretch that side. A side within 15 s of going both takes it back (`reverted`, or re-sides the both part); later, a side means "she's on the Left": tracking sides again (undo goes back to both). Pause, back on (resume on `"B"`), Done, Fix times and `setSide` ("That was both sides") work as for any part. Back and forth is its own bucket everywhere (`both` in `sideTotals`, `partTotals`, `FeedMinutes`, `both_sec` on a finished or by-minutes feed, "L 12 · R 9 · both 38"), counts toward nursing, and is never split into made-up Left and Right minutes; `first_side` / `last_side` skip it, so the start tap still decides the next side. A running both part isn't stale (`staleFeed`) for 2 hours, since it gets no taps by design. At 60 parts, going both turns the open part both instead of adding one. A paused feed at 60 parts can't go back on, Back and forth included (`too_many` with `paused`: "Tap Done and start her again"; MCP: stop_timer, then start_timer), since back on within 10 minutes still counts as the same feed.
  - **Feeds as counted** (worked out from the log, never stored: `nursingRuns`, `feedClusters`): off the breast under 10 minutes is the same feed whether Pause or Done was tapped (`SAME_FEED_MS`), so a feed paused 10+ minutes is two feeds and two feeds 5 minutes apart are one; three or more feeds, each starting less than 30 minutes after the last one ended, are a cluster (`CLUSTER_GAP_MS`). Bottles stay feeds of their own and never join a cluster. Each feed in a cluster counts toward the day's feeds ("11 · 4 in a cluster", the day line "11 feeds (one cluster)"), the same however it was tapped. `statsFor` takes the runs worked out from every loaded entry, so a feed that ran past midnight counts once, on the day it began, and its nursing minutes count with it (a day never reads 0 feeds with nursing minutes).
  - **Last fed** (`lastFedAnchor`, used by Today, the feed-gap checks and `maple_status`): from when her last feed began, start to start. A feed that went back and forth, or had 3+ parts, and ran past 40 minutes counts from 40 minutes before it ended (UNICEF UK's "between 5 and 40 minutes", `FEED_LENGTH_MIN` in `guidelines.ts`; using it this way is our choice). A feed left on one side keeps its real start, so a forgotten timer still shows its gap. So does a long feed whose last Left or Right alone ran past 40 minutes untouched (L, R, then L left on until morning), which counts from when she went on that side (`rule: "side"`). Back and forth gets no taps by design, so a long both part keeps the 40-minute rule. A later bottle wins.
  - **Next side** (`nextSideFor`): within 30 minutes of her last feed ending, the other side from the one she was last on (what the paused dock offers); after that, or while she nurses, the opposite of the side that feed started on (AAP's alternate rule, cited in `suggestNextSide`). A both-sides stretch never sets it; after back and forth it reads "Left, or the fuller side" (`fuller`, `NEXT_SIDE_NOTE`). The Done toast, and the feed sheet's toast for a feed logged by minutes, name the same side the card and the dock then show: "Left if she wants more" inside the 30 minutes, "Right next time" otherwise (`doneText` / `nextSideWords` in `useTimerActions.tsx`). "Usually every ~X" (`typicalFeedGapMin`) skips gaps inside a cluster.
  - **Timer API for it:** `start { kind: "feed", side, back_and_forth: true }` (side = where she started); `switch { id, side: "B" }` (back and forth from now); `switch { id, side: "L" | "R" }` while going both (tracking sides again); `resume { id, side: "B" }`; `reopen` / `join` and the Fix times edits take `"B"` too. Undo is `retime undo_tap` as for any tap (a start's is `discard` with `expect_updated_at`), with the same 409 `changed` races.
  - **Where it shows:** Last fed reads "Last fed 45m ago · Cluster 6:02–8:40 PM · 3 feeds · nursed 1h 52m" after a cluster ("Cluster" opens the Cluster feeding sheet), and otherwise its sides "Right first, then back and forth"; the dial stripes back and forth in both side colors (a crosshatch at night) and draws a thin bracket outside the feed ring for each cluster (a tap shows its line and feeds); the Timeline folds a day's cluster into one row that opens to its feeds. The row sits where its newest feed would be (as `list_entries` places its `feed_cluster` row), with that feed's time in the time column and the span in the line under it ("Cluster · 3 feeds   7:20 PM" / "6:50–7:40 PM · nursed 45m (L 20 · R 25)"), so a span across noon or midnight never cuts the count. It counts the cluster's own finished feeds as worked out from the whole log, so a feed's half from before a long pause isn't counted in it, and a side tapped under 10 minutes after its last Done (the same run, still running under Happening now) adds nothing to it. A past day's dial loads the day before too, so a feed that began late the night before counts on that night, as History's day line counts it. The dial's popover opens on whichever side of the tap fits between the top of the screen and the dock (with her strip on it); otherwise it opens on the roomier side, with its list capped and scrolling inside (a cluster's list opens at its newest feeds); Patterns' Left/Right split leaves out back and forth and says "not counting back and forth", and finds clusters with the same rule. The one sheet about it, `sheets/ClusterInfoSheet.tsx` (`useClusterInfo()`), shows guidelines.ts's cluster block word for word (clustering is normal, back and forth is fine and switch on her cues, the sore-nipple caution, diapers and weight show she's getting enough, who to ask, 911 signs) and how the log counts. The pediatrician line points at her targets on Today only while warnings are on; otherwise `clusterCall` states her day's diaper numbers itself ("on Day 5, at least 5 wet and 3 dirty a day"). No alert is about clustering.
- **The nursing screen:** the timer card only shows what happened, as labelled rows ("Left 4:00–4:10 · 10 min", "Break · 15 min", "Right side · since 4:25"), with the time on the current side as the big number and "Total nursing · break not counted" beside it. The dock is the only place with timer actions (Switch / Pause / Done / More, one meaning per column). Paused, column 1 is the other side ("Next side", where Switch was) and column 2 the side she came off ("Resume", where Pause was), so Pause and Resume toggle in one spot and a second Pause tap merges back with no break. The night Lantern holds the same actions in the same order (Switch, Pause, Done; paused: Next side, Resume, Done). Timer toasts wait while any sheet is open, and other toasts draw inside the sheet above its footer, so nothing covers a sheet's buttons.
  - "Total nursing" is whole clock minutes, the rows' rule (each side row's minutes plus the live side's), so it never jumps at a Switch or Pause and equals the Done toast; the big number is the current side's own m:ss.
  - Forgot to stop: once a side is past its "Still nursing?" check, the dock's Done says "when?" and opens "When did she finish?" ("Now" first) instead of ending it now; the Lantern asks the same. Snoozes ("Still going") are kept per part (a side or a break), so muting one never mutes the next.
  - **Back and forth on the dock, card and Lantern** (`useTimerActions.backAndForth`, `askSide`, `trackSides`). It's offered only where it's relevant: the switch toast from a feed's second Switch ([Back and forth] over the time it records, which it sends, so a toast held while the Lantern was open still records that time, then one "2 min earlier"); the start toast of a feed that starts within 30 minutes of the last nursing feed ending ([Back and forth] after "Same feed as 6:02" within 10 minutes); and always the card's … menu ("Back and forth · Stop tracking sides from now"; on a break, "Back on, back and forth"). Its toast reads "Both sides from 6:14 · no need to tap Switch", and Undo gives the side back. While she's going both, Switch's place in the dock is a quiet "Back & forth" tile (an LR mark, "Track sides" under it) that only asks "Which side is she on now?" in a toast, [Left] [Right], and saves nothing until one is picked, so a habit tap there is harmless; Pause and Done stay put, and the menu's "Track sides · Left / Right" does the same. Picking a side is "On the Left from 9:31 · tracking sides" (within 15 s of going both it takes that back), and its Undo goes back to both. A toast raised by a chip tap (this answer, a start's [Back and forth]) ignores taps on its own chips for its first 600 ms (`ToastBody` in `ui.tsx`), so a late second tap on [Left] never lands on "2 min earlier". On a break after it, column 1 is "Track sides" (the same question; it goes back on that side, or starts a new feed after an hour) and column 2, where Pause was, is "Back on · both sides", filled, so a late second Pause tap rejoins with no break; Done is "Done · ends 8:10". The card names the part "Both sides" ("Both" in the rows, with the LR mark; on a phone under 720px tall two or more past parts fold into the one "Earlier" row, so Left, Right, then back and forth still leaves the Since tiles above the dock), and on a phone 720px or taller a line under the clock says there's no need to tap Switch, with "About back and forth" (the Cluster feeding sheet; on a short screen it's in the … menu). Its "Still nursing?" waits twice the side check (90 minutes by default), since no Switch resets it. The Lantern offers "Going back and forth? Hold to stop tracking sides" from the feed's second Switch; while both, its heading is "Both sides" with an LR ring and only two big buttons stay, Pause and Done ("Back on" and "Done · ends 8:10" on a break); tracking sides again is the dock's. Every Lantern hold (the big buttons, her medicine row, the back-and-forth row) lets go if the finger moves more than 10px or leaves it, and the swipe down to close listens in the capture phase, so a swipe that starts on a hold row closes the Lantern and never logs a dose or goes both. Only one finger swipes: a second touch during a hold (her hand, a cheek) cancels the swipe until every finger is up. Fix times and the feed sheet fix a part's side three ways ("Wrong side? [It was Right] [Both sides]", "Only one side? [It was Left] [It was Right]"), "Already back on?" after a both part offers Both too, and the feed sheet's minutes have a "Back and forth" field (`both_sec`; Started on still says where she latched).
  - After this phone's own tap, column 1 stays off for 2.5 s (column 2, 1.2 s), so a late double tap can't land on the tile that replaced it; a Switch within 15 s of the same person's resume fixes that resume's side instead (`resided`). Discard asks first once a timer has run 2 minutes.
  - A paused feed nobody came back to for over an hour is stale (Siri's rule, judged by its newest tap that wasn't taken back): the dock's and the Lantern's side buttons say "New feed", ending it at its pause and starting a new one in one toast (Undo brings the old one back paused), and the card's "Still on a break?" leads with "She's done" ("Same feed, back on…" second).
  - "Same feed as 8:30" (the start toast, and Fix times on a one-side feed started within 30 min of a timed feed ending) is one request, `join`: the new feed is set aside (`joined_into`, so Recently removed doesn't offer it back) and the old one carried on from its start; a Done tapped within a minute of the new start leaves no break. A Continue's resume is marked `carried`, so Fix times doesn't offer an undo_tap that would leave it paused (its toast's Undo restores the Done).
  - Done past "Still nursing?" opens Fix times as "Done" (`fixPreset("current", "done")`): "Now" first, hours for a side left on for hours, "likely" exactly 15 min on the side; if the other phone ends or switches the feed meanwhile, it asks about the side she's on now, or says it ended.
  - Done records `stopped_at` (when it was tapped), so a Done that set an earlier end isn't read as an edit; the sheet says "edited" only for a later fix, "ended by Brittany" when someone else's last write was their Done.
  - A breast feed with no minutes can't be logged by hand ("Add how long she nursed"). After every tap a toast offers "2 / 5 min earlier" for that tap alone, and **Fix times** (the card button, or any row) opens `sheets/FixTimesSheet.tsx`, which starts on the right question ("Was she on the Right before you tapped?").
  - Timer writes go through `mutateTimer` in `store.ts`: read, apply the intent with the engine, write only if the row is unchanged, retry up to 3 times. Two phones' changes merge instead of overwriting.
  - REST: `POST /api/maple/timer` with `action: "retime"` and an `edit` (`move`, `set_side`, `undo_tap`, `add_part`, `restore`); switch/resume/pause/stop take an optional `at`. Every fix response carries `before` (with `paused_at_stop` when the feed had ended at its pause), which the toast's "Back to …" restores exactly.
  - **Carrying a finished feed on is one write.** `reopen` takes an optional `side` (+ `at`) and `expect_updated_at` (`reopenTimerDetailed` in `store.ts`): ended at its pause, she goes back on that side at `at` (default now), a resume after the break with the resume's rules; ended while running, with no `at` (the dock's stale Switch), the side she was on runs to the Done and she switches there (the same side just runs on); with an `at` after the Done ("Same feed as 8:30", from the new feed's start), she came off at the Done and goes back on at `at`, so the gap is a break. Changed since this phone looked: 409 `changed`, nothing written. The answer carries `before` (the finished feed). The client's `continueFeed(e, side, at?)` uses it for the dock's "Continue that feed on Right", Fix times' "Continue it on Right" and the start toast's "Same feed as 8:30"; the toast says where she is and that "the 8:10 feed goes on", and its Undo is one checked `restore` back to the finished feed.

  - `add_part` (`{ side, start, end, expect_updated_at }`) adds a side to a finished feed (`addPart`): `ended_at` moves to its end and `paused_at_stop` clears; changed or reopened since, 409 `changed`.

(only for a tap made in the last 10 minutes that undo would really take back).

  - **Done while paused ends the feed when you paused** (flag `paused_at_stop`; Undo brings it back paused).

Paused after going both, `switch_side` with no `to` goes back on going both. `start_timer {timer:"nursing", side, back_and_forth:true}` starts a feed going both from the start (side is required: where she started, which the next side alternates from); with a feed running it's `switch_side {to:"both"}`. `log_feed` and `log_many` take `both_minutes` (stored as `both_sec`, never split into left and right; `update_entry` takes `both_sec`). A feed logged with both_minutes ends on back and forth, as its sides read, so like a timed one it never sets a re-latch side (the next side alternates from where she started). `fix_nursing_time` takes `part: "both"` and `set_side: "both"` ("that was both sides"); `undo_last_tap` after going both gives the side back. Replies say "Going back and forth (both sides) since 6:14 PM", timelines "Both sides 6:14–6:52", JSON `side: "both"` / `back_and_forth: true` / `both_minutes`, and every reply after going both says not to call `switch_side` at each change.

## For mom

Her own area: medicines on the schedule her clinician gave, her temperature, questions for her OB, a daily check-in (with an optional PHQ-9 and GAD-7), warning signs after the birth, help lines and a page for partners. It's a tab of its own, labelled with her first name (`care/CareScreen.tsx`), for everyone who can read her page: the tab bar, the picker's "Brittany's page" row (the picker opens from her strip on Today's dock) and a reminder's tap open it. Support, warning signs and Help open for everyone signed in, viewers included.

**Her tab**, short and ordered by use: her name with the same day count as Today's hero ("Day 6") and a Help button; the crisis strip when it's up; a row of actions (Took a medicine → the picker, Temperature → her temperature sheet, Question for her OB → the add field, Notifications → this phone's sheet); her medicines, one row each in her list's fixed order (`care.rows`): the pill badge, `PlanName`, the glance and Took it with all its safety rules, and a tap opens that medicine's detail (schedule, the last 7 days, Edit, Stop); notes about a medicine's own numbers (over the limit) under the list; one-time medicines; Something else, Finished (folded) and Medicine questions; the check-in; temperature; OB questions; one Help group (Warning signs, Supporting Brittany, Help lines and doctor numbers); her care team; and Settings (Notifications, Settings for this page, and a line that a notification can't ring through Silent, so the Mom meds shortcut can start a timer instead). Skipping a set-time dose is in its Dose sheet (Took a medicine → the medicine). Sheets open from here at most one deep. It's about 2,300 px at 375 wide, against 3,700 for the old full-height sheet.

**The rules it's built on.**
- **Her data lives only in `maple_care_*`.** No Maple path reads it: not the Timeline, Patterns, Moments, the dial, celebrations, While you slept, Recently removed, the CSV export, `AlertStack`, or Maple's MCP `list_entries`, `daily_summary`'s paragraph and per-day rows, `update_entry` and `delete_entry` (`undo_last` takes back her newest entry when it's newer than Maple's, and `log_medicine` notes when her mom has a medicine by that name, or the same medicine by its other name; `daily_summary` ends with a separate line, and `mom` in its JSON, for her own doses, temperatures and OB questions, only for someone who can read her page). Nothing about her goes in `maple_babies.settings`.
- **One rule for who sees it** (`careAccess()` in `src/lib/maple/care.ts`): everyone who can sign in to Maple's Log (owners, members, the family's admin login and the calendar connector) sees and does everything on her page; view-only guests don't. There's no per-person sharing and no "Only me". Roles are read fresh on each request, so a demoted or removed member loses it at once.
- **It works like Maple's log: no setup.** Her page always exists: `getCarePerson()` makes the one `maple_care_people` row (`DEFAULT_CARE_PERSON`, "Brittany", a plain name, so she needs no sign-in of her own) on the first read, the way the migration makes Maple's row. Deleting the page clears everything and an empty one takes its place.
- **No dose numbers anywhere by default.** Every number on a plan (how often, the 24-hour limit, how many each time, course length) is typed by the family from her label, discharge papers or clinician; fields start blank and no placeholder or hint has a digit (`npm run check:maple-care` fails on one). The app only does arithmetic on her numbers: "OK after", "OK since", "by your schedule", never "take", "due" or "time for".
- **Limits are in the label's own unit** (tablets, caplets, capsules, doses or mL), and the 24-hour count adds up each dose's units, not the taps.
- **Doses save like Maple's entries.** "Took it", Siri and the MCP save at once; early, at the limit or with the count left out still saves, and the toast or result carries the note (`earlyDose`, `overDailyMax`; a call-now note's whole text). A count left out counts as the most of a choice, or one when the plan doesn't say (`countedAs`), and every channel says what it counted as. An "At set times" dose more than an hour early says which time it counted for (`aheadOfSlot`). The only ask is a likely duplicate: anyone's dose of the same medicine within 30 minutes (`RECENT_MS`), plus a medicine whose doses for today are all logged, in the app. A name counts toward a plan by its name or an Also called name (`matchPlan` in `care.ts`), or one of those plus only strength and form words ("Tylenol Extra Strength", "Advil Liqui-Gels", "Ibuprofen 600"; `SAME_PRODUCT_WORDS`). Any other extra word makes it another product, which never counts toward the plan: "Tylenol 3", "Tylenol PM" or "with codeine" is a one-time medicine with its own notes (the codeine label note among them), and a plain name that's only part of a longer plan name ("tylenol" when her list has Tylenol PM, "vitamin" for Vitamin D3 and Vitamin C) asks which. On Claude and Siri, a brand or generic name of a medicine on her list counts toward it ("acetaminophen" for a plan named Tylenol, "Advil" for one named Ibuprofen; `SAME_MEDICINE` in `care-mcp.ts`: single-ingredient names only, matched exactly after `normName` and without strength or form words, never a combination product like Percocet or Tylenol PM, and only after her own names and Also called found nothing; two plans of one medicine ask which). A dose said with another strength still counts toward her plan, so its gap is kept, and the reply says what it counted as. Any other name is saved as a one-time medicine (her screen and `mom_status` list the recent ones); a `p…` id that isn't on her list never becomes a name. Half a tablet is fine; notes are cut to 2000 characters, like Maple's. Edits to her entries are last-save-wins.
- **One rule picks her line, and Took it never lands on the wrong medicine.** Today's strip, the Lantern and `maple_status` show her most pressing active medicine by one rule (`pressingPlan` in `care.ts`, by its own ranking (`PRESSING`): a set time that's passed and isn't logged (`slot_open`), then OK again (`ok`), then doses left today (`day_open`), then the soonest wait or at the limit (`wait` / `at_limit`), then as needed with no gap (`unknown`), then none logged yet (`none`), then the next set time (`slot_next`), then all logged today (`day_done`); within a rank, `sortPlans`' order. The lists read out under a cap, `maple_status` and Siri's "Maple status", put that one first and the rest after it (`pressingFirst`)). There's no Show on Today switch any more; `validate.ts` still accepts and stores `show_on_today` (older app versions and Claude chats send it), but nothing reads it. Lists with a Took it on every row (the picker, her tab) keep one fixed order (`listOrder`: her list's order, then the order they were added), never re-sorted by status. After a save on this phone, that medicine holds its slot for a minute everywhere (strip, picker, her tab, the Lantern): "Logged 6:56 AM" with a check, not a button, while Undo stays in the toast; an Undo ends the hold at once. Where the medicine under the thumb can change (the strip, the Lantern), Took it ignores taps while a dose is saving and for 1.5 s after any care save (only care's: the dock's own buttons never wait on it), so a double tap 0.9 s apart can't log a second medicine. Lists that keep their order (her tab, the picker) pass `cool: false`: two medicines taken together are two quick taps, and both save. Took it wears a quieter look (the sunken pill of vitamin D's "Log") while it isn't OK yet (wait, at the limit, next set time, today's all logged); it still saves at once. Its accessible name names the medicine ("Took it: Brittany's Examplex (Brandex)").
- **Names: "Examplex (Brandex)".** `planTitle(plan)` in `care.ts` is the name plus the first Also called name that isn't the name again. The strip, the picker, her tab, the Dose sheet, toasts and the Lantern use it; Siri and the MCP keep `plan.name`. On a narrow line the Also called name drops out whole before the name is cut (`PlanName` in `care/parts.tsx`). The glance (`planGlance`) is UI only: Siri's and the MCP's sentences don't change.
- **Medical copy** (warning signs, crisis card, notes, help lines, screener text) lives only in `guidelines.ts`, word for word, with its sources. Alerts say who to call (`MOM_TIER_LABEL`, or the alert's own label such as "Call Poison Help now"); readers who aren't her see "For {Name}: " before the title.

**Tables** (`src/lib/migrate.ts`):
- `maple_care_people`: the one care person per log (a single-row unique index) and `settings` (care team numbers including her therapist, nursing yes/no, next OB visit, check-in suggestions, note acks). `shared_with` is a leftover and isn't used.
- `maple_care_meds`: her plans. `schedule` is as needed (optional gap), every N hours, N times a day, or set clock times; `max_24h` needs `limit_unit`; `units_per_dose` is her own text ("2", "1 or 2"); `private` and `reviewed_at` are leftovers (nothing reads them: a plan Claude added reads like any other). Left out, how often is As needed with no gap, never a made-up number.
- `maple_care_entries`: doses (taken or skipped, with `units` and the plan's unit at the time), temperatures and questions. Soft deletes with Undo.
- `maple_care_mood`: check-ins and fuller check-ins, hard-deleted, its own sequence.
- Plan and entry ids are random 8-digit numbers (`care-store.ts`). The MCP prints them as `p12345678` (plans) and `c12345678` (entries).

Errors on care routes, `care-mcp.ts` and the Siri mom actions are reported as `new Error(code)` with `{ route }` only, since Postgres messages can hold row data.

**App** (`src/components/maple/care/`): `useCare()` is the reader's view (null without access). `CareNav.tsx` (mounted in `MapleApp`, inside `AppNav`) opens her tab (`openCare()` switches to it; `openQuestion(text?)` switches to it at the OB question field) and holds the sheets, opened with `useCareNav()`: Support, warning signs, the plan picker, the Dose sheet, her temperature (`openTemp()`), Help (`openHelp()`) and For the doctor (`openDoctor()`). Tapping the line opens the picker. It's hidden for view-only guests and when she has no active medicines. Outbox items carry `target: "entries" | "care" | "mood"`; an old item without one still goes to `/api/maple/entries`. Her check-ins wait there too while offline (a change to a saved one goes as a PATCH); signing out drops `care` and `mood` items.

**Check-ins** (`CheckIn.tsx`, `FullCheckIn.tsx`, `CheckInResults.tsx`; rows in `maple_care_mood`, through `/care/mood`; everyone signed in sees them in the app):
- **The daily check-in** sits on her screen under Medicines: "How are you doing?", one tap on Good, Okay, Up and down, Low or Really struggling saves it, then "Anything else?" adds chips (`MOOD_TAGS`) and a note to the same row. "Change" within 30 minutes corrects it; later it's another one. "Your check-ins" lists the last 14 days. There's no graph, score, streak or badge, nothing names a condition, and deleting one is a hard delete.
- **What it answers** ignores `show_alerts` and every other setting: "Really struggling" shows `STRUGGLING`, "Scary thoughts I don't want" shows `INTRUSIVE`, "Thoughts of hurting myself" opens the crisis sheet at once, and days 0–14 after the birth add `BLUES_NOTE`. `HELP_ROW` ("Need to talk now? Call or text 988 · Call 911") is always under the card and the results.
- **The fuller check-in** is the PHQ-9, then the GAD-7, then the difficulty question when any answer was above "Not at all", one question per screen and word for word from the developers' forms (free to reproduce; the EPDS isn't used, since republishing it online needs RCPsych's written permission). Question 9 above "Not at all" opens the crisis sheet at once with `CRISIS_LEAD` and saves the answers so far right away (later answers update that row), and `item9_ever` stays set even if she goes Back and changes it. It saves as one `screen` row, scored on the server; "Stop here" saves it unfinished. - **Suggestions** (her switch "Check-in suggestions", on by default): with no fuller check-in in 14 days, on days 14–20 after the birth, or in the 7 days before "Next OB visit". "Not now" dismisses that one for good (`acks["suggest:…"]`).
- **Not in the export, Siri or any MCP tool:** there are no mood tools; the crisis numbers are in `MAPLE_INSTRUCTIONS` itself, so they never depend on a tool call.

**API** (`/api/maple/care/*`, wrapped by `withCare`): `person` (PATCH settings, DELETE; no POST, since the page always exists), `meds` (POST, PATCH `?id=` with `expect_updated_at`, `stopped`; DELETE), `entries` (GET by local days, POST, PATCH, DELETE) and `entries/restore`, `mood`, and `move` (a Maple medicine entry to her dose, in one statement, with an undo). **MCP tools** (`care-mcp.ts`, on both the Maple connector and the calendar connector): `mom_status`, `log_mom_medicine`, `set_mom_medicine`, `add_mom_medicines`, `log_mom_temperature`, `add_mom_question` and `fix_mom_entry`, each titled with her name ("Brittany's medicines right now"; `MOM` is `DEFAULT_CARE_PERSON`, since titles are fixed when the server starts; results use her page's own name). - `MAPLE_INSTRUCTIONS` names her (built from `DEFAULT_CARE_PERSON`): the opening paragraph ends "Her mom is Brittany: Brittany's own medicines use the mom tools, never Maple's.", and a paragraph before the medicines one says "Brittany", "mom", "my wife", or "I/me" when she's the one talking mean the mom tools, "she" and "her" mean Maple, and when the medicine named is also on her list (by its name, an Also called name, or its brand or generic name) and the user didn't say whose dose it was, Claude asks "Maple's or Brittany's?" before logging anything (`log_medicine`'s and `log_mom_medicine`'s descriptions say the same; `log_medicine` takes `for_maple: true` once they say Maple's), and a brand and its generic name are one medicine. The medicines paragraph and the crisis numbers stay word for word (§10.1; `scripts/maple-care-check.ts` checks it): call 911 if anyone is in immediate danger, otherwise call or text 988; the maternal hotline isn't a crisis line.
- **From a photo of her label or discharge papers** (the family's yes): Claude may copy her medicines into her list. It copies each value exactly as printed (name, dose, how often, the most in 24 hours with its unit), leaves out anything that isn't printed, reads every medicine and number back, and saves only after an explicit yes. It never invents, guesses, suggests or fills in a number that isn't on the paper, and a 24-hour limit with no unit printed is left out and said so. The rule is in `MAPLE_INSTRUCTIONS` and in both adding tools' descriptions.
- `add_mom_medicines` takes the whole list (up to twelve) in one call with no destructive hint, so the Claude app asks at most once. It needs `read_back_confirmed: true` (the schema says so, and the handler saves nothing without it): the user said yes to the read-back of every medicine and number. A line already on her list (its name or an Also called name, or the same medicine by another name, so a discharge sheet's "Ibuprofen 600 mg" is the "Motrin" she has; `alreadyOnList`) is left as it is and says to use `set_mom_medicine`; a line that can't be saved (a limit with no unit) says why while the rest save, so a retry of the same list adds nothing. If the database drops out partway, the lines already saved are said and the rest are marked not saved (a retry is safe). `set_mom_medicine` won't add a second plan for a medicine she has unless `separate: true` (the user says it's a second, separate plan). Every new plan's line says what isn't on file, as facts: "Saved p…: Examplex · as needed. Not on file: the dose, how long between doses (so no gap is checked) and a 24-hour limit (so there's none to count against)." (the gap only for As needed, the limit only for As needed and Every few hours). `set_mom_medicine` adds the same line on an add, and keeps its destructive hint for changes, stops and deletes.
- `log_mom_medicine` saves like `log_medicine`: a name on her list counts toward it, so does its brand or generic name (the result says so: "Saved c…: acetaminophen at 2:10 AM today (logged by Matt via Claude), counted toward Examplex on her list (the same medicine).", with `same_medicine` in the JSON), any other is a one-time medicine, and only a likely duplicate (30 minutes) answers `created: false` with `possible_duplicate` until called again with `allow_duplicate: true`. Early or over her limit, the alert comes with the saved dose. `set_mom_medicine` saves only what the user read from the label, or what's printed on a photo they shared, and leaves the rest empty (a 24-hour limit still needs its unit); it no longer takes `show_on_today` (nothing reads it); without `how`, the number given decides it (`every_hours` → every), and on a change a new type without its number keeps the schedule she has. `stop: false` takes a finished one again and `restore: true` brings back a deleted one. `undo_last` after one of these, or after `fix_mom_entry`, removes nothing and says how to undo it. `fix_mom_entry` takes `minutes_ago` as well as `at` for a corrected time (not both).
- `mom_status {medicine}` with a brand or generic name of one on her list answers for that one, led by "\"acetaminophen\" is the same medicine as Examplex on her list, so a dose by either name counts toward it." (`same_medicine` in the JSON); "isn't on her list" only when nothing matches.
- The one access error (a viewer) ends with `HELP_NOW_LINE` and carries `help_now: MOM_HELP.now`.
- Maple's `log_medicine` (and a `log_many` medicine item) always logs for Maple, with Maple's own age cautions. When the name exactly matches (after `normName`) an active plan or Also called name on her list, or is the same medicine by its other name (`SAME_MEDICINE`), the result adds that her mom has it ("Brittany has Examplex on her medicine list, the same medicine as acetaminophen.") and how to move it (`undo_last`, then `log_mom_medicine`); `for_maple: true` leaves that line out. It still saves for Maple, with Maple's own age cautions. Vitamin D never trips it.
- `maple_status` carries every active medicine of hers, most pressing first by the one rule (`pressingPlan`): the text line "Brittany's medicines: Examplex OK after 9:10 AM; … ; 2 more in mom_status." (up to three), and `speak` ends with "Brittany's medicines: Examplex OK since 2:10 AM; Samplex OK after 10:55 AM, and 1 more." (capped at two). `json.mom` has `name`, `line`, `top`, `speak`. Viewers get none.
- `daily_summary` (Claude's summary, not a Maple view) ends with one line for her when she has any doses or temperatures in the window or open OB questions, and `mom` in the JSON: doses per medicine with the last one ("Examplex 3 doses and 1 skipped, last 2:10 AM today"; one-time medicines marked), her temperatures (count, highest), and her open OB questions. Never her check-ins, never in Maple's paragraph or per-day rows, never for a viewer.

**Siri** (`POST /api/maple/quick`, a personal token, `careAccess` on the Siri channel; viewers get 403):

- `mom_dose` with `{ med, minutes_ago?, skipped?, units?, confirm?, client_id?, name_in_reminder? }` (`med` is a name, Also called, its brand or generic name, or a `p…` id; any other name is a one-time medicine). Only a likely duplicate comes back `ok: false` with `needs_confirm` and a question to speak; it's saved once `confirm: true` comes back. A save answers "Got it, Examplex at 3:02. - Family → Shortcuts & assistants shows the one "Mom meds" shortcut for her plans, next to Maple's: mom_status, Choose from List, mom_dose, the duplicate ask, Speak Text, and an optional Start Timer for `next_ok_in_minutes` (a timer rings through Silent; Apple Reminders at `next_ok_at` works too). Not a calendar: family calendars show on the kitchen display.

**Her medicines' notifications** (OK again, set times, Logged) are described with the rest under [Notifications](#notifications).

**Help lines** are one constant, `MOM_HELP` in `guidelines.ts`, verified on `HELP_VERIFIED_ON` (2026-10-24) against each line's own page; `npm run check:maple-care` fails once that's more than 183 days old, so recheck every number and its hours before then. Don't copy numbers from secondary pages: some official pages still show retired or mistyped ones (NIMH's "1-833-9-TLC-MAMA", CDC's retired "1-833-9-HELP4MOMS", and 1-800-273-8255).

**Sources** are next to each constant in `guidelines.ts`. The main ones: AWHONN's POST-BIRTH warning signs (paraphrased, never reproduced), CDC Hear Her, NIMH on perinatal depression and postpartum psychosis, ACOG Clinical Practice Guideline 4 and FAQ091, ACOG Committee Opinion 736 (the postpartum visit), Postpartum Support International, 988lifeline.org, HRSA's National Maternal Mental Health Hotline, Poison Help (poisonhelp.org), MotherToBaby, the InfantRisk Center, NLM LactMed, the FDA labels quoted for codeine, tramadol and the opioid note, and the PHQ-9 and GAD-7 developers' official forms (word for word; the EPDS isn't used, for licensing).


## Notifications

Web Push, turned on phone by phone (on iPhone only from the Home Screen app, iOS 16.4+). Each phone's choices live with its subscription on the server (`maple_push_subs.prefs`), so the server knows what to send where. Code: `src/lib/maple/push.ts` (sending, ticks, health), `push-wake.ts` (when, and the QStash clock), `notify.ts` ("Logged" and the nursing timer), `push-hooks.ts` (the write hooks), `device.ts` (the per-install id), `/maple/sw.js` (the service worker), and the app's side in `src/components/maple/notify/` (the provider, the sheet and its row).

**What can be sent** (examples use a made-up medicine, Examplex):

| Notice | Who gets it | When | Default |
|---|---|---|---|
| Her medicine is OK again | Every phone of a family member with her medicines on (viewers never) | Once per phone when an as-needed or every-few-hours medicine's gap and 24-hour limit have both cleared after a dose | On |
| Set time | Same | At each set time no dose or skip has filled (the app's own slots, so a dose an hour early counts for its time) | On |
| Logged | Phones that got that medicine's reminder since its previous dose (up to 12 hours), plus phones with "every dose" on; never the phone that logged it | Seconds after a dose or skip is saved from the app, Siri or Claude | On |
| Every dose logged elsewhere | Phones that turn it on (`prefs.logged`) | Any dose of hers, even with no reminder pending | Off |
| Nursing timer on the lock screen | Every phone that turns it on (`prefs.nursing`), the one that started the feed included | Start, switch, break, back on, done, removed (and a fix while it runs) | Off |
| Test reminder | The phone that asked | One minute after "Send a test in 1 minute", through the scheduled path | On demand |

Nothing else notifies: no "timer left running", no morning summary, no readings, no feed-gap nags, and never anything about check-ins, the crisis sheet, OB questions or notes. "N times a day" medicines and as-needed ones with no gap or limit can't remind (there's no time to remind at); `GET /api/maple/push` says so per medicine (`reminders`), so the sheet never shows a switch that can't fire.

**The words.** Never a dose, never "take it now", "due" or "time for": the times are her own plan's. No person is ever named (phones aren't people); where a dose came from reads "On another phone.", "From Siri." or "From Claude.". Her own phone (signed in as herself) reads "your"; every other phone reads "for Brittany".
- OK again: "Examplex is OK again for Brittany" / "OK since 2:10 AM, by her schedule. Last taken 8:10 PM." More than 10 minutes late (the clock was down): "Examplex has been OK for Brittany since 2:10 AM" / "By her schedule. Last taken 8:10 PM.". More than 3 hours late it isn't sent at all.
- Set time: "Examplex · 8:00 AM for Brittany" / "One of Brittany's set times. Tap to log it once she's taken it."
- Logged: "Examplex logged for Brittany · 2:10 AM" / "On another phone. OK after 8:10 AM, by her schedule." (or "Next set time 8:00 PM."); a skip: "Examplex: 8:00 AM set time skipped".
- Hide medicine names: "Maple's Log" / "One of Brittany's medicines is OK again, by her schedule." (and the same for set times and Logged).
- Nursing: "Nursing · Left" / "Since 2:05 AM. Tap to open."; "Nursing · Right" / "Since 2:17 AM · feed started 2:05 AM"; "Nursing · on a break" / "Since 2:30 AM"; "Fed 23 min · L 14 · R 9" / "Done at 2:28 AM"; "Feed removed". Silent (no sound), no emoji; a tap opens `/maple`.

**On the lock screen.** Every notice about a medicine has the tag `med:<planId>` and every feed `nurse:<entryId>`. iOS ignores tag replacement, so the worker closes the notices the new one replaces before showing it (`getNotifications()`): the same tag, any other feed's nursing notice, and medicine notices older than 12 hours. So "Logged" replaces "OK again" instead of stacking, and the nursing notice is always the one feed as it is now (two quick taps that cross keep the newer one). A tap on a medicine notice opens `/maple?care=1&plan=<id>`, Logged opens `/maple?care=1`. The worker asks an open app to go there itself (`postMessage({ type: "maple-open", url })` with a MessageChannel; the app answers `{ ok: true }`), so a half-filled sheet survives; with no answer in 600 ms it navigates the window. Each push also carries a `Topic`, so a phone that was offline gets only the newest notice per tag, and a TTL of what's left of the 3-hour window (nursing: 15 minutes).

**Sent once, even when sending fails.** Nothing is queued: each tick works out what's due from the plans and doses as they are now (`dueMoments` in `push-wake.ts` is the only place that decides when), so a dose logged, moved or deleted never leaves a stale reminder. Every send is claimed per phone in `maple_push_sent` (`s<subId>|ok:<plan>:<dose>`, `…|at:<plan>:<slot>`, `…|log:<dose>`, `…|nurse:<entry>:<version>`). A send the push service refuses for now (429, 5xx, a timeout) gives its claim back: it's tried again after 50 seconds, up to 3 attempts, and with QStash a retry wake is published for a minute later. 404/410, or a 403 about keys, marks the phone `needs_resubscribe` (the sheet shows Stopped) and it gets nothing until it turns notifications on again; its row and settings stay, so turning it back on (`{ replaces }`) keeps hidden names and muted medicines. A phone left stopped for 30 days is deleted. "Logged" and the nursing notice aren't worked out from the plans, so the tick re-sends one that failed (`retryWriteNotices`, within the hour, still up to 3 attempts), and a failed one asks for its own retry wake. The retry wake is timed from the end of the run, so every claim it made is past its 50 seconds. One phone's or one member's trouble never stops the rest of the run.

**The clock.**
- **Upstash QStash (the real clock).** Every write of hers (a dose, a skip, an edit, a delete or restore, a plan saved, stopped or deleted, a move out of Maple's log) from any channel runs `careChanged()` after the response (`after()`): "Logged", a tick, and then `scheduleWakeups`, which publishes a delayed QStash message (`Upstash-Not-Before`) for each of the next 3 moments within 7 days (and any pending test) to `/api/maple/push/tick`. Turning a phone on (or moving it, or changing its settings) runs `scheduleWakeups` too, so the family's first phone gets the reminders its dose toast promised. A moment already published is a `wake:<second>` row, so it's never published twice; nothing is ever cancelled (a stale wake just finds nothing to send). On time to within about 10–20 seconds. A QStash schedule, `maple-tick-net`, runs the tick every `MAPLE_TICK_NET_MIN` minutes (default 30, at :04 and :34 like the GitHub backstop, so they wake Neon together; 0 turns it off) while any phone has notifications on, and is switched off when none does. QStash's requests are signed (`Upstash-Signature`, checked with `QSTASH_CURRENT_SIGNING_KEY` / `QSTASH_NEXT_SIGNING_KEY`); a signed call skips the 20-second gate.
- **The GitHub workflow** (`.github/workflows/maple-reminders.yml`, every 5 minutes, `X-Maple-Via: gh`) is a best-effort backstop: GitHub runs scheduled jobs late or not at all under load. Once QStash is set up, the tick route answers runs away from :04 and :34 (the safety net's minutes) with a 204 before touching the database, so Neon can sleep.
- **An open app's polls** run a tick after answering (throttled), but never publish anything. While QStash is set up, a poll leaves a pending test to the clock, so the test says whether the clock works.
- **A cron with `Authorization: Bearer $CRON_SECRET`** (for example a daily Vercel cron to `/api/maple/push/tick`) counts as trusted (`via=daily`) and re-arms everything.
- **Without any QStash env vars** nothing is published: the GitHub workflow (every 5 minutes, when GitHub runs it), open apps and writes drive the tick. Health says `mode: "fallback"`.
- The tick answers 204 with no body to everyone (a count would tell an outsider when her medicines come up), and 500 to a trusted caller when it fails, so QStash retries.
- Neon: QStash wakes touch the database only around real moments, plus the safety net (every 30 minutes is about half the compute of every 15). A one-minute pinger would keep Neon awake all day; don't use one.

**"The other phone".** The app sends a per-install id with every request (`X-Maple-Device`, `localStorage["maple-device"]`, from `deviceId()` in `src/lib/maple/device.ts`). It's stored on the phone's subscription (`device_id`; a phone that was on before ids existed gets its id from its next check, `GET /api/maple/push`, and the migration gave every phone a receipt token), on her doses and on Maple's timers (`device` columns that nothing in Maple's views reads), and used only so "Logged" skips the phone that did it. It's never shown, never names anyone and never decides access. Siri and assistant writes have none.

**Receipts and health.** Each payload carries the phone's receipt token and the notice's key; the worker posts them to `POST /api/maple/push/receipt` right after showing it (no session: the 128-bit token is the proof; always 204), which sets `last_delivered_at` and resets `undelivered`. `GET /api/maple/push?endpoint=` returns `health`: the clock (`mode`, `net_min`, `checked_at` for any tick, `clock_at` for the server's own, `clock: "on_time" | "late"`, `next_wake_at`), this phone's `last_sent_at`, `last_delivered_at`, `undelivered` (2 or more: they aren't arriving), `needs_resubscribe`, its latest `test` (`due_at`, `sent_at`, `via`, `arrived_at`), long `gaps` in the server's checks and `missed` reminders in the last 12 hours, and this member's `phones` (labels only, never endpoints). A missing receipt isn't proof a notice failed (iOS can show a notice without running the worker), so "didn't reach" waits for two in a row.

**Send a test in 1 minute.** `POST /api/maple/push/test { endpoint, in_seconds: 60 }` sets `test_due_at`, and a QStash wake sends "Test reminder" / "This phone gets reminders, even when it's locked." through exactly the path a 3am reminder takes (wake → tick → push service → worker → receipt), so it can be checked with the phone locked. `test_via` says which tick sent it (`poll` means only because an app was open). With `all: true` an owner sets one for every phone on that login (the shared admin login's phones included). Without `in_seconds` it sends "Notifications are on" at once.

**On the phone.** `NotificationsProvider` (`src/components/maple/notify/`, mounted once in `MapleApp`) holds this phone's state and renders the one Notifications sheet, portaled to `<body>` so it opens on top of whatever asked for it. `useNotifications()` gives `status` (`on`, `off`, `stopped`, `denied`, `install` for an iPhone Safari tab, `unsupported`), `prefs`, `health`, `value` (the row's "On", "Off", "Stopped", "Home Screen app first", or "On · may be late" while the server's clock is behind) and `open()`, `turnOn()`, `turnOff()`, `setPrefs()`, `testInOneMinute()`, `sendNow()`, `refresh()`, `forgetThisPhone()`; `NotificationsRow` is the "Notifications" row in Family → On this phone and on her tab.
- **The sheet**, top to bottom: what's in the way (Home Screen steps in a Safari tab, "off in Settings", or "Stopped" with a Turn on button); the switch; her medicines for anyone who can see them (Reminders, When one is OK again, At set times, Logged on another phone, Every dose logged elsewhere, Hide medicine names, then each medicine with what it can do: "When it's OK again", "At 8:00 AM and 8:00 PM", or a row with no switch, "No reminder: this one has no set times." / "No reminder: no gap set."); Maple's "Nursing timer on the lock screen" (off by default); "Check it works": the server's clock and this phone's last delivery ("Checked 2 min ago. Last one reached this phone at 3:10 AM.", "Last checked at 1:40 AM, so notifications may be late. For a dose that matters overnight, set an alarm too.", two undelivered in a row, a reminder a gap made impossible), **Send a test in 1 minute** (it re-reads every 5 seconds until the test arrives, says when it came only because the app was open, and asks "Did it show up?" when the worker sent no receipt), "Send one now", and for owners "Test every phone"; the Silent and Focus footnote; and "Phone settings that help" (iPhone and Android settings paths, Apple Watch mirroring, Show Previews).
- **Asked when it matters.** After a dose is saved on a phone whose notifications are off (supported, not denied) and that medicine has a next time by her schedule, the dose toast gets a "Remind me / at 12:56 PM" chip beside the time fixes. One tap turns this phone on (the permission prompt is asked inside the tap, before anything waits) and says "Notifications are on for this phone. It'll say when Examplex is OK again, at 12:56 PM.". In an iPhone Safari tab it reads "Get reminders on this phone" and opens the Home Screen steps. At most 3 times per phone (`localStorage["maple-remind-offers"]`), never once on, never beside a call-now note.
- **Checked on each open** (on load and on coming back, at most once an hour), for members and viewers alike: the browser's subscription is compared with what the server has and what this phone remembers (`localStorage["maple-push-endpoint"]`: the endpoint it turned on, and for whom). An endpoint the browser swapped is saved again quietly with the old one's settings; a subscription that's gone, was made with an old key, is `needs_resubscribe`, or that the server dropped reads **Stopped**, with a toast "Notifications stopped on this phone. Turn them back on?" (Turn on / Not now; at most once a day, three days after Not now). Turn on always makes a fresh subscription and keeps the phone's settings.
- **Stale notices** are closed while the app is open: a medicine's "OK again" or set time once a dose (or skip) of it was logged after it went out, a feed's notice once the app shows that feed finished, and any medicine or nursing notice older than 12 hours.
- **A tapped notice with the app open**: the provider answers the worker's `maple-open` by putting the sheet away and handing the URL to the app as a `maple-open` window event (CareNav routes it); `/maple` alone is answered at once.
- **Signing out** turns this phone's notifications off first (`forgetThisPhone()`: DELETE, then unsubscribe); if the session ends some other way while the app is open, the browser's subscription is dropped too, so the server forgets it at its next send.

**Routes.** `GET/POST/PATCH/DELETE /api/maple/push` (this phone's key, health and reminder facts; a viewer's health has no `next_wake_at` or `missed`, which are her medicines' times; subscribe with `X-Maple-Device`, or `{ replaces }` from the worker's `pushsubscriptionchange`; prefs; turn off), `POST /api/maple/push/test`, `POST /api/maple/push/receipt`, `GET/POST /api/maple/push/tick`. Prefs (each phone's, replaced whole by PATCH): `meds` (her medicines at all, default on), `ok` (OK again, default on), `at` (set times, default on), `closing` (Logged after a reminder this phone got, default on), `logged` (every dose, default off), `hide_names`, `muted` (plan ids), `nursing` (default off).

**Keys.** VAPID keys come from `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` when set, else they're derived from `MCP_SECRET` (or `GOOGLE_CLIENT_SECRET`). Changing that secret changes the keys and every phone has to turn notifications on again, so pin them first (step 5 below).

### Setting it up (the family's part)

1. **Check the Neon plan** before anything runs on a schedule: console.neon.tech → the brooker-wedding project → Billing (or Usage). Note the plan and this month's compute hours. On Free, keep `MAPLE_TICK_NET_MIN` at its default of 30; on Launch or higher, 15 is fine.
2. **Add QStash (free):** Vercel dashboard → brooker-wedding → Integrations → Browse Marketplace → Upstash → add **QStash** and connect it to the brooker-wedding project for Production. That adds `QSTASH_URL`, `QSTASH_TOKEN`, `QSTASH_CURRENT_SIGNING_KEY` and `QSTASH_NEXT_SIGNING_KEY`. Or: console.upstash.com → QStash → copy those four into Vercel → brooker-wedding → Settings → Environment Variables → Production.
3. **Optional:** `MAPLE_TICK_NET_MIN` (15 or 30) in Vercel Production. `CRON_SECRET` already exists for the calendar sync; a cron that calls the tick with it is trusted.
4. **Redeploy** so the variables apply: Vercel → Deployments → latest Production → ⋯ → Redeploy (or push any commit to `main`).
5. **Pin the push keys** once, and always before changing `MCP_SECRET`: from the repo, run `MCP_SECRET='<the production value>' npx tsx -e 'import("./src/lib/maple/push").then((m) => console.log((m.vapidKeys ? m : m.default).vapidKeys()))'`, add the printed `publicKey` and `privateKey` as `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY` in Vercel Production, and redeploy. They're the same keys the phones already use, so nothing changes for them.
6. **Check the clock:** console.upstash.com → QStash → Schedules lists `maple-tick-net` (it appears after the first write or tick once a phone has notifications on), and Logs show 2xx deliveries to `/api/maple/push/tick`.
7. **On each iPhone:** Settings → General → About should say iOS 16.4 or later (18.4+ is better). In Safari open brooker.family/maple → Share → Add to Home Screen, open Maple from the new icon and sign in again (the Home Screen app keeps its own storage), open Family → On this phone → Notifications (or the Notifications row on her tab), turn it on → Allow, then **Send a test in 1 minute** and lock the phone.
   - Settings → Notifications → Maple: Allow Notifications, with Lock Screen, Notification Center, Banners and Sounds.
   - Settings → Focus → Sleep → Apps (under Allow Notifications) → Add → Maple, and the same for Do Not Disturb or any Focus used at night. Maple shows up in that list only after it has been opened from its Home Screen icon once.
   - Nothing rings through the Ring/Silent switch. For a dose that must not be missed overnight, also set a Clock alarm (or, on iOS 26.2+, a Reminder marked Urgent).
   - If others can see the lock screen: Settings → Notifications → Show Previews → When Unlocked, or turn on Hide medicine names.
8. **On an Android:** in Chrome open brooker.family/maple → ⋮ → Add to Home screen → Install, open it from the icon, sign in, turn notifications on → Allow → send a test. Settings → Apps → Maple → Notifications: allowed; add Maple to Do Not Disturb's apps if you use it.
9. **Leave the GitHub backup on:** GitHub → the brooker-wedding repo → Actions → Maple reminders, not disabled.
10. Whenever a phone shows Stopped (the row, or the "Notifications stopped on this phone" toast), is reset, or has its Home Screen icon removed: open Maple from the icon, tap Turn on, and run the 1-minute test with the phone locked.
